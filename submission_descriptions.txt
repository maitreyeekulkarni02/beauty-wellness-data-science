Week 1 Submission Description

This report presents a clearly scoped data science problem in the beauty and wellness sector, focusing on customer preferences for skincare products and the relationship between product/review characteristics and recommendation outcomes. It explains why beauty retailers and brands need evidence beyond star ratings alone, including the importance of review volume, product categories, price, review text, and data quality. The report defines the business problem, project aim, objectives, research questions, and testable hypotheses. It also specifies the unit of analysis, potential target variables, candidate predictors, and the conditions under which the study would switch from recommendation classification to rating prediction. The proposed workflow covers business understanding, public-data assessment, preprocessing, exploratory analysis, feature engineering, model comparison, validation, and communication of findings. Ethical and methodological risks are addressed, including self-selection bias in online reviews, incomplete metadata, possible manipulation, leakage, and the risk of interpreting predictive association as causation. The project is designed to produce useful decision support for product discovery and marketing, not clinical recommendations or claims about product safety. Success will be judged by reproducibility, appropriate validation, traceable data sources, transparent limitations, and actionable conclusions. The report distinguishes hypotheses from findings and does not claim model performance before the analysis is run on an identified dataset.

Week 2 Submission Description

This report documents a structured strategy for identifying, obtaining, and assessing data for the skincare customer-preference project. It prioritizes a publicly documented skincare reviews dataset and describes the fields needed to answer the research questions, such as review ratings, recommendation labels, review text, dates, product identifiers, category, brand, and price where available. It evaluates supplementary sources, including an official cosmetic adverse-event reporting API and a general retail transaction dataset, while explaining why those sources should not be merged casually with the core reviews. The report outlines a step-by-step collection process: review source metadata and license, download permitted files, store original data locally, record retrieval details and hashes, inspect the schema, profile quality, and document transformations. The proposed exploratory analysis includes descriptive statistics, missingness summaries, category-level comparisons, rating distributions, review-volume trends, and visualizations. It maps the proposed analyses to the hypotheses and recommends appropriate statistical tests depending on the variable types and distributional assumptions. Data quality considerations include duplicate records, missing fields, inconsistent categories, malformed dates, price parsing, and possible sampling bias. The report also addresses privacy and reproducibility by recommending that raw data and unnecessary personal text remain out of version control. The resulting plan gives a reviewer a clear view of how the project will obtain evidence, assess its reliability, and prepare a defensible analysis without fabricating data or results.

Week 3 Submission Description

This report describes a reproducible data cleaning and preprocessing pipeline for public skincare review data. It identifies likely quality issues such as missing values, duplicate reviews, inconsistent text and category formats, invalid rating values, price parsing errors, malformed dates, and inconsistent recommendation labels. The proposed pipeline preserves raw source files and creates cleaned outputs alongside an audit log, making the transformation process transparent and repeatable. The report explains how column names are standardized, numeric and date fields are parsed, text whitespace is normalized, duplicates are identified, and unusual values are flagged for investigation rather than automatically deleted. It provides guidance for handling missing values based on the role of each variable, including removing rows with missing supervised-learning targets, imputing predictors inside training pipelines, and retaining missingness indicators when justified. It also discusses encoding categorical features, scaling numeric features, and preventing data leakage by fitting transformations only on training data. The accompanying Python scripts implement a starter version of the pipeline using pandas, NumPy, and scikit-learn-compatible conventions. The report includes a high-level flow of the preprocessing stages and explains how the resulting clean data improves reliability for exploratory analysis and modeling. Importantly, it avoids claiming a specific number of removed rows or corrected errors until the code has been run against the actual downloaded dataset. This makes the deliverable technically honest and suitable for reproducible project work.

Week 4 Submission Description

This report provides a detailed exploratory data analysis and feature-engineering plan for understanding skincare customer preferences. It begins with data-quality profiling and univariate summaries, then progresses to comparisons across product categories, price bands, review periods, and other fields that are genuinely present in the source dataset. The proposed visualizations include rating distributions, missingness charts, category counts, rating comparisons, review-volume trends, and selected numeric relationships. Statistical techniques are chosen according to the data structure and assumptions, with an emphasis on effect sizes and cautious interpretation rather than relying on p-values alone. The feature-engineering section proposes review length, time-derived variables, category encoding, price bands, log-transformed review volume, and optional text representations when suitable source fields exist. It emphasizes that each feature must be available at the intended prediction time and that transformations must be fitted on training data only. Particular attention is given to target leakage, repeated reviews for the same product, and the distinction between review-level and product-level conclusions. The report also includes a conditional business scenario showing how different patterns might guide product-page improvement or additional investigation, while explicitly identifying these scenarios as examples rather than measured findings. The expected outputs are data profiles, plots, feature definitions, and a concise interpretation of patterns supported by the actual analysis.

Week 5 Submission Description

This report defines a predictive modeling strategy aligned to the project's business question and the target fields available in the selected dataset. It explains that binary classification is appropriate only when a reliable recommendation label exists; otherwise, rating prediction is treated as a limited proxy task. A dummy baseline is included so that more complex models must demonstrate real value rather than merely produce a score. Logistic regression and random forest are proposed for classification, with corresponding regression alternatives when the target is numeric. The report compares their interpretability, ability to model nonlinear patterns, and potential limitations. It describes a train/test split, cross-validation, and the need for grouped-by-product or time-based validation when records are related. Evaluation metrics are explained in business language, including precision, recall, F1-score, ROC-AUC, confusion matrices, MAE, and RMSE as appropriate. The report also discusses overfitting, underfitting, class imbalance, feature leakage, preprocessing pipelines, and the importance of excluding direct identifiers from ordinary predictors. It outlines how model coefficients or permutation importance may support interpretation while warning that feature importance is not evidence of causation. No numeric performance result is promised in advance. Instead, the project code will generate metrics from the real dataset, and any model that fails to outperform a baseline will be reported honestly with recommendations for further data collection or target redesign.

Week 6 Submission Description

This final report sets out a transparent framework for evaluating predictive models and communicating their implications to non-technical stakeholders in the beauty and wellness industry. It defines a staged evaluation process covering data verification, baseline comparison, model selection, held-out testing, product-grouped or time-based robustness checks, error analysis, and business communication. The report explains precision, recall, F1-score, ROC-AUC, confusion matrices, MAE, and RMSE in practical terms and links metric selection to the relative costs of false positive and false negative predictions. It specifies appropriate tables and charts, including model-comparison tables, confusion matrices, ROC or precision-recall curves, feature-importance plots, and predicted-versus-actual charts where relevant. It also proposes an error-analysis process that checks whether performance varies across product categories, price bands, or time periods, while avoiding unsupported claims for small groups. Business recommendations focus on cautious uses such as analyst shortlisting, product-page improvement, and identifying areas where customer feedback is noisy. The report explicitly rejects using the model to diagnose skin conditions, prove product safety, or make unsupported efficacy claims. It discusses public-review bias, changing consumer preferences, data drift, governance, and the need for a controlled pilot before deployment. The conclusion connects technical quality to business value: recommendations should be proportional to the evidence, and weak or unstable model performance should lead to better data collection rather than automatic decision-making.
